# Отчёт о соответствии Java и Go

Что именно проверено, чем, и где ещё расхождения. Пишется по ходу, а не в конце:
отчёт, собранный задним числом, всегда оптимистичнее правды.

**Состояние на 27 августа: игра целиком работает на Go.** Домен, REST и WebSocket
перенесены; матч играется настоящим фронтом в браузере против Go — впервые за миграцию.
Схема базы и ассеты карт больше не принадлежат Java. Ни одна строка ниже не закрыта
«по факту компиляции».

---

## 1. Как проверяется

Четыре независимых уровня, как требует документ. Работают три:

| Уровень | Состояние | Чем |
|---|---|---|
| Перенесённые тесты | ✅ домен целиком | `go test ./internal/domain/game/` — 191 тест |
| Совместимость данных | ✅ проверена вживую | токен, пароль и хеш refresh от живой Java |
| Differential | ✅ по REST | `tests/contract/compare.mjs` — 7 сценариев, 25 запросов, **различий нет** |
| Differential сыгранного матча | ✅ в ОБЕ стороны | `tests/contract/matchdiff.mjs` — история, разбор, реплей, рейтинг |
| Golden-фикстуры | ⬜ не начаты | — |
| Сквозной прогон | ✅ матч целиком | `go test ./internal/server/` — от регистрации до `MATCH_OVER`, рейтинг и история в базе |

### ⭐ Инструмент сравнения проверен с обеих сторон

«Различий нет» ничего не стоит, пока не показано, что инструмент их **видит**.
`compare.mjs --selftest` прогоняет семь пар и требует, чтобы он заметил пропавшее поле,
лишнее поле, `null` против отсутствия, смену типа и разный код ошибки — и при этом
**не считал различием** разные идентификаторы и время.

Самопроверка запускается перед каждым прогоном: неисправный нормализатор врал бы
в самую опасную сторону — молчанием.

---

## 2. Совместимость данных — доказана прогоном

Не рассуждением о совпадении форматов, а материалом, взятым у **живой Java**:

| Что | Как проверено | Результат |
|---|---|---|
| Access-токен | зарегистрировался на Java, её токен отдан Go | ✅ принят |
| Хеш пароля | `password_hash` (`$2a$10$`) прямо из базы | ✅ принят |
| Хеш refresh-токена | токен от Java + её `token_hash` из базы | ✅ совпал побайтно |
| Схема БД | репозитории работают на Postgres 16 с миграциями Java | ✅ |

⚠️ Последнее было самым коварным: сам токен кодируется url-safe **без** паддинга,
а его хеш — стандартным Base64 **с** паддингом. Два кодирования в одном классе Java,
без единого комментария. Перепутать — и переключение выкинуло бы из игры всех.

Тесты берут материал из окружения и пропускаются без него: держать чужой ключ доступа
в репозитории нельзя.

## 3. Differential: что уже совпадает

Прогон `OLD=Java NEW=Go node tests/contract/compare.mjs`:

| Сценарий | Состояние |
|---|---|
| health | ✅ |
| регистрация и профиль | ✅ |
| ошибки регистрации | ✅ |
| столы | ✅ |
| рейтинг и статистика новичка | ✅ |
| друзья | ✅ |
| каталоги | ✅ |

**Итог прогона: различий нет.** Сравниваются статус, имена полей, типы и — отдельно —
наличие или отсутствие поля.

### Найденные и закрытые различия

1. **Ошибка валидации без `details`.** Java отдаёт разбор по полям, Go не отдавал.
   Экран подсвечивает по нему конкретное поле. Закрыто.
2. **Тексты внутри `details`.** Были русские, стали дословно как у Bean Validation,
   вплоть до английского. Игроку они не видны (фронт показывает только `message`), но
   проверка сверяет их посимвольно, и «улучшенная» формулировка светилась бы вечно.
   ⭐ Улучшать надо в Java первой — тем же правилом, что и починки.
3. **Неизвестный путь: 401 против 404.** Java отвечает 401, потому что Spring Security
   срабатывает раньше маршрутизации. Go повторил порядок: авторизация до маршрутизации.
   Сервер не сообщает, существует ли адрес, тому, кто не представился.
4. **Невалидный UUID в пути: 500 против 400.** Агенты писали по контракту, снятому ДО
   того, как это было починено в Java. Поведение приведено к исправленному.
   ⚠️ Урок: документ аудита устаревает, как только чинишь исходник, — и переносчик
   честно повторяет вчерашнюю ошибку.
5. **Текст сообщения при отсутствующем логине.** Выровнен дословно.
6. ⚠️ **Видимость событий в журнале матча.** `private_to_seat` не записывалась, а
   отклонённая попытка называлась `ATTEMPT_REJECTED` вместо `MOVE_REJECTED`. Вместе это
   значило, что после `RESYNC` чужая вскрытая карта и чужие неудачные попытки уезжали
   соседям — то есть чтение чужой руки и чужих намерений. Имя пришло из плана; в коде
   Java его нет, и аудит это прямо отмечал (`java-reference/websocket-contract.md` §6.1).

7. ⚠️ **Разбор ничьей мастей при выборе козыря за молчащего.** Java берёт `max` по
   компаратору с ОБРАТНЫМ порядком по `ordinal`: читается как «старшая масть», выбирает
   первую. Расхождение всплыло бы только на равенстве — редко и необъяснимо.

8. ⚠️ **Экранирование HTML в JSON.** Кодировщик Go по умолчанию превращает `<`, `>` и `&`
   в `\u003c`, `\u003e`, `\u0026`, а Jackson их не трогает. На сегодняшних данных
   незаметно, но первое же имя за столом с амперсандом дало бы расхождение — и искали бы
   его долго, потому что глазами оба ответа выглядят одинаково. Выключено, закрыто тестом,
   тест проверен обратным ходом.

   Нашёл это не differential-прогон, а внимательное чтение: на текущих данных он бы молчал.

## 4. Сознательные различия

Пока таких нет. Всё найденное приводилось к поведению Java.

⚠️ Единственное отличие по устройству, не по поведению: **Go не воспроизводит
`java.util.Random` побитово** (MD-005). Колода из одного seed у двух бэкендов разная.
Это безопасно и проверено по коду: восстановление матча идёт из полного снимка,
реплей — из записанных событий, колода из seed заново нигде не выводится.

Следствие: differential не сравнивает карты в раздачах, начатых каждым бэкендом
самостоятельно. Это предусмотрено требованиями (§11.3 прямо разрешает нормализовать
случайную колоду).

## 5. Что ещё не проверено

Честно и без смягчений:

- ~~Не покрыты differential-ом ручки, требующие сыгранного матча~~ — **покрыты
  27 августа** (`tests/contract/matchdiff.mjs`). Оба бэкенда смотрят в одну базу, матч
  играется ботами на каждом, и каждый матч читается обоими: история, разбор, реплей,
  рейтинг, статистика. ⭐ Проверяются САМИ ДАННЫЕ, а не формы: различие здесь означало бы
  не «поле переехало», а «игрок увидит другую партию».
  ⭐ Проверено в ОБЕ стороны: Go читает матч Java (это переключение) и Java читает матч Go
  (это откат). Проверять одно направление значит закрыть себе половину пути.
  ⚠️ Реплей сравнивается по ПОРЯДКУ и ИМЕНАМ событий, а не по телам: карты в матчах разные
  по построению (MD-005).
  ⭐ Инструмент проверен обратным ходом: переименовал `dealsPlayed` в Go — оба направления
  покраснели, назвав поле и место.
- REST перенесён целиком и совпадает с Java на всех семи сценариях.
  ⭐ Сам путь завершения матча теперь проверен сквозным прогоном: два «робота» доигрывают
  матч действиями, которые предложил сервер, и в базе оказываются места, степени, рейтинг,
  история рейтинга и сыгранные раздачи. Отказов в этих прогонах ноль — ни одно предложенное
  действие сервер не отклонил.
- WebSocket перенесён вчерне целиком: конверт, рукопожатие, рантайм, идемпотентность,
  оба маршрутизатора, часы хода и пауза, итог матча с рейтингом. **Differential по сокету
  не гонялся ни разу** — сравнение с Java здесь пока держится на чтении её кода и на
  перенесённых сценариях, а не на прогоне двух бэкендов рядом.
- **Прогон настоящего фронта состоялся — и нашёл поломку, из-за которой игра не запускалась
  вообще.** Живой снимок отдавал внутренние имена полей (`hungCards` вместо `hung`,
  `roundStarterSeat` вместо `attackerSeat`), и фронт падал на старте матча с белым экраном.
  ⭐ Это ровно тот риск, который здесь был записан: differential по сокету не гонялся
  ни разу. Он и не гонялся — поломку нашли глазами, по стеку из браузера. После починки
  фронт открывает стол, ходит, видит ответ соперника и обновление состояния; имена полей
  снимка закреплены тестом по ПОЛНОМУ списку.
- **Присутствие игроков в Go не заводил никто.** `Presence.Attach` не вызывался ни из
  одного места: друзья не загорались «в сети» никогда, приглашение за стол не доходило
  по сокету ни разу и молча уезжало в push. Нашёл прогон ботов `tools/smoke/friends.mjs`
  (3 проверки из 10 падали), закрыто сквозным тестом.
- **Схемой базы владеет Go** (MD-006): пустая база поднимается одним `go run ./cmd/server`,
  живая база Flyway принимается как своя без выполнения миграций. Проверено на настоящем
  Postgres, включая отказ от чужой базы.
- **Ассеты карт переехали** в `assets/` в корне: каталог Java больше не нужен для игры.
- **Push-уведомления перенесены и подключены.** Стол зовёт того, чей ход, если его нет
  за столом, зовёт обратно пропавшего, из-за которого матч встал на паузу, и догоняет
  уведомлением приглашение ушедшему другу. Окно тишины, присутствие по подписке и тексты
  совпадают с Java; проверено 31 тестом и обратным ходом. ⚠️ Не проверено ЖИВОЙ доставкой:
  настоящего push-сервиса браузера в тестах нет, и сравнения с Java на одних и тех же
  ключах VAPID не проводилось.
- Golden-фикстуры не сняты — заменены решением владельца на сквозной прогон до ручек,
  прогон ботов и прогон настоящего фронта.
- Нагрузочное сравнение Java и Go не проводилось. База для него есть: Java на 160 столах
  даёт p95 6 мс при 380 потоках (ADR-062).
- ~~Полный игровой сценарий ФРОНТА против Go не прогонялся ни разу~~ — **прогнан
  27 августа**: регистрация, лобби, создание стола, приглашение, готовность, старт матча,
  ход и ответ соперника в настоящем браузере. Не пройдено до конца в UI: доигрывание
  матча до итога и экран результата — они проверены сквозным тестом и ботами.
- ⚠️ **Игрок не может вернуться в идущий матч через интерфейс после перезапуска сервера.**
  Комната ожидания предлагает «Начать матч», сервер честно отвечает «Матч уже идёт»,
  и на этом путь заканчивается. Найдено тем же прогоном; в Java поведение не проверялось.

⭐ Прогон фронта против Go остаётся главным незакрытым риском, но «ни разу» уже неверно
для самого сервера: сквозной тест играет матч по настоящему сокету против настоящей базы.
Он нашёл ДВЕ поломки, которых не нашли шестьдесят модульных тестов, и обе — про контекст
HTTP-запроса, который после апгрейда сокета живёт недолго:

1. команда стола исполнялась с контекстом СОКЕТА — закрытая сразу после хода вкладка
   отменяла запись этого хода в журнал;
2. запись в сокет шла с контекстом ЗАПРОСА — сервер молча переставал отправлять, и стол
   у игрока выглядел зависшим, хотя на сервере всё шло своим чередом.

Обе невозможно увидеть без настоящего сокета. Живая игра снова оказалась строже тестов.
