# front-bardak

Фронтенд игры — PWA. Этап **M1**: страница-проба, показывающая ответ `/api/health`
и живое WS-эхо.

## Запуск

Отдельного dev-сервера пока нет: в dev-профиле фронт отдаёт Spring прямо из этой папки.
Подними бэкенд (см. `../back-bardak/README.md`) и открой **http://localhost:8088/**.
Правка файла + перезагрузка страницы — изменения видны сразу, пересборка не нужна.

## Стек

- Сборка: **пока никакой.** Нативные ES-модули, работают в браузере как есть.
- Фреймворк: **не выбран.** См. OQ-4 в `../planning/10-open-questions.md`
- PWA: `manifest.json`, Service Worker, Web Push (VAPID) — этап M7

### Почему без Vite

На машине стоит **Node v10**, а Vite требует 18+. Для M1 сборщик и не нужен: браузер сам
понимает `import`. Когда Node обновится, добавляются `package.json` и `vite.config.js`,
фронт переезжает на порт 5173 с proxy на `/api` и `/ws` — он уже указан в
`bardak.ws.allowed-origins`. Код при этом не меняется: он и так на ES-модулях.

## Требования, не зависящие от выбора фреймворка

1. **Клиент не знает правил.** Он рисует состояние и отправляет намерения. Список разрешённых
   действий приходит от сервера в `STATE_SYNC` — фронт не вычисляет легальность хода сам.
2. **Клиент не получает скрытую информацию.** В состоянии — свои карты целиком, у остальных
   только количество. Никакого «спрятать через CSS».
3. **Устойчивое WS-соединение**: reconnect с экспоненциальным backoff, heartbeat, очередь
   неотправленных команд, ресинк по `RESYNC(last_seq)`.
4. **Оффлайн-оболочка**: app shell и ассеты набора карт кешируются Service Worker'ом.
   Партия без сети не идёт, но приложение открывается и показывает состояние соединения.
5. **Обновление SW не рвёт партию**: новая версия применяется после выхода из-за стола.
6. **Ассеты карт грузятся по манифесту набора**, а не хардкодом путей —
   см. `../planning/06-card-design-system.md`.
7. **Адаптив**: до 5 позиций игроков вокруг стола, портрет и ландшафт, safe-area на мобильных.

## Структура

Есть сейчас:

```
front-bardak/
├── index.html
├── styles.css
└── src/
    ├── main.js              # страница-проба M1
    └── net/
        ├── rest-client.js   # fetch + единый формат ошибок
        └── ws-client.js     # backoff, heartbeat, очередь неотправленных команд
```

Появится дальше:

```
    ├── state/           # проекция серверных событий в состояние UI       M4
    ├── ui/              # лобби, стол, профиль, история                   M3
    ├── render/          # отрисовка карт, анимации раздачи и хода         M4
    └── assets-loader/   # манифест набора карт и предзагрузка ассетов     M3
public/                  # manifest.json, иконки                           M7
sw.js                    # Service Worker                                  M7
```

`ws-client.js` уже реализует backoff, heartbeat и очередь команд — не «на вырост», а потому,
что без них соединение неотличимо мёртвое от живого, и это мешает уже сейчас.
