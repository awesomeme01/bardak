# Наборы дизайна карт

Каждый набор — папка с картинками. Один набор = один комплект карт, выбирается при создании
стола. Подробности модели — `planning/06-card-design-system.md`.

```
card-sets/
├── classic/          ← набор по умолчанию
│   ├── 6-diamonds.png … A-diamonds.png
│   ├── 6-hearts.png   … A-hearts.png
│   ├── 6-spades.png   … A-spades.png
│   ├── 6-clubs.png    … A-clubs.png
│   ├── Joker.png
│   └── back.png
└── <новый-набор>/    ← та же структура
```

## Имена файлов — это контракт

| Что | Имя | Примеры |
|---|---|---|
| Карта | `<ранг>-<масть>.png` | `6-diamonds.png`, `10-hearts.png`, `A-spades.png` |
| Джокер | `Joker.png` | один файл на всех джокеров |
| Рубашка | `back.png` | |

- Ранги: `6 7 8 9 10 J Q K A`
- Масти: `diamonds`, `hearts`, `spades`, `clubs`
- Всего: **36 + Joker + back = 38 файлов**

Имя файла совпадает с кодом карты в БД и в протоколе — никакого преобразования между ними
нет. Поэтому переименовывать файлы нельзя: на эти коды завязан весь исторический лог партий.

Джокеров в колоде столько, сколько игроков (`Joker-1` … `Joker-5`), но рисуются они одним
файлом `Joker.png`.

## Как добавить набор

1. Создать папку с кодом набора.
2. Положить все 38 файлов с точными именами.
3. Зарегистрировать набор (SQL-миграция на MVP, позже — админский эндпоинт).

Сервер проверяет полноту покрытия при регистрации: набор с пропущенной картой нельзя выбрать
при создании стола.

## Требования к картинкам

- Соотношение сторон одинаковое у всех карт набора (ориентир 180×252, ~1:1.4).
- Прозрачный фон по скруглённым углам, если карты со скруглением.
- PNG. SVG тоже допустим — тогда расширение `.svg` и `format: "svg"` в манифесте.
