# 08 — Роадмап

Каждый этап имеет **явный критерий готовности** — проверяемое утверждение, а не «сделано».
Этапы идут последовательно; параллелить бэк и фронт можно начиная с M3.

---

## M0 — Репозиторий и документация ✅ текущий

Структура репозитория, planning-доки, `.gitignore`, README.

**Готово, когда:** структура на месте, документы читаемы, открытые вопросы выписаны.
Кода нет.

---

## M1 — Каркас, который запускается

- `back-bardak`: Gradle (Kotlin DSL), Spring Boot 3, Java 21, зависимости (web, websocket,
  security, data-jpa, validation, actuator, flyway, postgresql).
- `docker-compose.yml`: Postgres.
- Первая Flyway-миграция (пустая или `users`).
- `GET /api/health`.
- WS-эндпоинт `/ws` с эхо-ответом (пока без авторизации).
- `front-bardak`: Vite-скелет, страница-заглушка, вызов `/api/health`, подключение к `/ws`,
  вывод эха на экран.

**Готово, когда:** `docker compose up -d && ./gradlew bootRun`, открыт фронт, на странице
видно ответ `/api/health` и эхо из WebSocket. Связка живая от браузера до Postgres.

## M2 — Авторизация

- `users`, `refresh_tokens` + миграции.
- Регистрация, логин, BCrypt.
- JWT access (короткий) + refresh (с ротацией).
- `SecurityFilterChain`, JWT-фильтр.
- ⭐ `POST /api/auth/ws-ticket` и авторизация WS-handshake по одноразовому тикету.
- Фронт: экраны регистрации и входа, хранение токенов, авто-refresh.

**Готово, когда:** незалогиненный не может открыть WS-соединение и не может дёрнуть
`/api/profile`; залогиненный видит своё имя и держит WS-соединение.

## M3 — Лобби и столы

- `card_sets`, `card_assets`, `table_themes` + дефолтный набор-заглушка (SVG с рангом и мастью).
- `game_tables`, `table_players`.
- REST: список столов, создание с выбором набора и темы, детали, вход по коду.
- WS: `TABLE_JOIN` / `TABLE_LEAVE` / `TABLE_READY`, события `PLAYER_JOINED/LEFT/READY`.
- `TableRuntime`: реестр столов, очередь команд, поток на стол.
- Фронт: лобби, создание стола с выбором набора карт, «комната ожидания» с живым списком.

**Готово, когда:** двое в разных браузерах видят вход друг друга за стол в реальном времени;
занять место за полным столом невозможно (проверено гонкой).

## M4 — Игровой движок: каркас раздачи ⭐

Основная интеллектуальная часть проекта.

- `game.engine`: **без Spring, без БД, без сети**.
  - модель: `Card`, `Suit`, `Rank`, `Seat`, `DealState`, `MatchState`;
  - `sealed interface Command` / `sealed interface GameEvent`;
  - автомат раздачи `DEALING → ATTACK → DEFEND → RESOLVE → REFILL → DEAL_OVER`;
  - `apply(state, command) -> (newState, events)` — чистая функция;
  - детерминированная сдача от seed.
- ⭐ Персональная проекция `project(state, seat) -> PlayerView`.
- ⭐ Все игровые числа — из `rules_config`, в коде движка ни одного литерала (ADR-016).
- `matches`, `deals`, `match_events`, `match_snapshots` + запись лога.
- WS-протокол: `PLAY_CARD` с обязательной целью у защиты, `PASS`, `TAKE`.
- ⭐ Таймеры в `TableRuntime`: ход 30 с; отключение → `PAUSED` с остановкой таймера,
  невозврат за 60 с → `ABORTED`.
- Тесты движка по списку из `03-domain-rules.md` §7.

**Готово, когда:** три человека играют одну раздачу от сдачи до «дурака»; защита без указания
целевой карты отклоняется; ни в одном сообщении, ушедшем клиенту, нет чужих карт (проверено
чтением трафика); выдернутый интернет ставит игру на паузу и возвращает без потери хода;
тесты движка проходят без поднятия Spring-контекста.

## M5 — Правила бардака и структура матча ⭐

- ⭐ `AttackOrderPolicy` = `BardakStrictNeighbours`: подкидывает начавший раунд, после паса —
  строго второй сосед (следующий по часовой за защищающимся), право назад не возвращается.
- Лимиты атакующих карт: 5 до появления отбитых, 6 после (OQ-12).
- Переводы (OQ-9).
- Джокеры (после ответов на OQ-2).
- ⭐ **Автомат матча**: перераздача после исчерпания карт, сквозной счёт, `scoreLimit`,
  под-seed на каждую раздачу, `deal_results`.
- Тип проигрыша по итоговому состоянию стола (после OQ-11).
- `rules_config` на столе, `rules_snapshot` в матче.

**Готово, когда:** матч идёт через несколько раздач с перераздачей и накоплением счёта и
завершается по достижении `scoreLimit`; попытка подкинуть из «неправильного» кресла или после
собственного паса отклоняется сервером; матч целиком воспроизводится из seed + команд.

## M6 — История и рейтинг

- `match_players`, `user_rating`, `rating_history`.
- Запись результата матча + пересчёт рейтинга в одной транзакции; `ABORTED` рейтинг не трогает.
- Elo с попарным разложением по итоговым местам матча.
- REST: история матчей, детали, разбивка по раздачам, `/replay` (только для завершённых и
  отменённых, через проекцию).
- Фронт: профиль с рейтингом и графиком, список матчей (включая отменённые с причиной),
  просмотр реплея.

**Готово, когда:** после матча у всех участников изменился рейтинг, матч виден в истории со
счётом по раздачам, отменённый матч виден с причиной и без изменения рейтинга, реплей
проигрывается по шагам через границы раздач.

## M7 — PWA

- `manifest.json`, иконки, установка на домашний экран.
- Service Worker: app shell + cache-first для ассетов набора карт.
- Обновление SW не рвёт идущую партию.
- Web Push + VAPID: уведомление «твой ход» при закрытой вкладке.
- Восстановление соединения: backoff, heartbeat, `RESYNC`, очередь неотправленных команд.

**Готово, когда:** приложение ставится на телефон, открывается офлайн (оболочка), приходит
push «твой ход»; выключение и включение сети посреди партии не ломает игру.

## M8 — Навесы и масштабирование

Порядок внутри этапа зависит от того, что понадобится раньше.

- ⬜ **Навесы** — как только правила будут описаны (OQ-3). Точка расширения в автомате
  зарезервирована на M4, начисление очков в счёт матча — на M5. Это последний недостающий
  кусок игры: до навесов счёт не растёт, и матч держится только на `scoreLimit`-заглушке.
- Несколько параллельных столов уже работают с M3; здесь — нагрузочная проверка.
- Redis: presence, pub/sub, распределённая блокировка стола.
- Sticky routing по `table_id` для второго инстанса.
- Партиционирование `match_events`.

**Готово, когда:** навесы играются; два инстанса за балансировщиком обслуживают разные столы
без расхождений.
