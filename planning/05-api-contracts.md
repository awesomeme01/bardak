# 05 — Контракты API: REST и WebSocket

## Разделение

- **REST** — всё, что не является ходом в живом матче.
- **WebSocket** — матч и live-события.

Граница проведена в `02-architecture.md`. Практическое следствие: создание стола — REST,
вход за стол — WS.

Терминология: **матч** = игра в бардак до предельного счёта, **раздача** = партия дурака
внутри матча (см. `03-domain-rules.md` §0).

---

# REST

Базовый путь `/api`. Аутентификация — `Authorization: Bearer <access_token>`.

## Формат ошибок

Единый для всех эндпоинтов, отдаётся из `@RestControllerAdvice`:

```json
{
  "code": "TABLE_FULL",
  "message": "За столом нет свободных мест",
  "traceId": "b1f2...",
  "details": { "tableId": "..." }
}
```

`code` — машиночитаемый, стабильный. `message` — для человека, может меняться.

## Auth

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/auth/register` | `{username, displayName, password, email?}` → `{accessToken, refreshToken, user}` |
| `POST` | `/auth/login` | `{username, password}` → то же |
| `POST` | `/auth/refresh` | `{refreshToken}` → новая пара (с ротацией: старый отзывается) |
| `POST` | `/auth/logout` | Отзывает refresh-токен |
| `POST` | `/auth/ws-ticket` | ⭐ Одноразовый короткоживущий тикет для WS-handshake |

**Про `ws-ticket`.** Браузерный `WebSocket` не позволяет задать заголовок `Authorization`.
Варианты: токен в query (утекает в логи прокси и живёт часами), subprotocol (костыльно),
одноразовый тикет. Выбран тикет: клиент получает `{ticket, expiresIn: 30}`, открывает
`wss://.../ws?ticket=...`, тикет сгорает при использовании. Даже попав в лог, он бесполезен.
ADR-005.

## Matches / History

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/matches?userId=&status=&page=` | История матчей: дата, участники, счёт, места, дельта рейтинга, отменённые с причиной |
| `GET` | `/matches/{id}` | Детали матча: раздачи, счёт по раздачам, итог |
| `GET` | `/matches/{id}/deals` | Разбивка по раздачам (`deal_results`) |
| `GET` | `/matches/{id}/replay` | Лог событий матча для реплея |

⚠️ `/replay` доступен **только для завершённых или отменённых** матчей и отдаёт события через
ту же проекцию, что и live-игра. Отдать сырой `match_events` — значит раскрыть скрытую
информацию: по нему читаются чужие руки.

Отменённые матчи (`ABORTED`) в истории видны с причиной и пометкой «не влияет на рейтинг».

# WebSocket

Эндпоинт: `wss://host/ws?ticket=<one-time-ticket>`

## Транспорт: сырой WS + JSON, не STOMP

ADR-002. Причины:

1. Нужны **персональные проекции состояния** — каждому игроку своё сообщение со своими
   картами. Модель STOMP «топик → все подписчики получают одно и то же» работает против
   задачи; пришлось бы заводить топик на игрока, и выгода исчезает.
2. Собственный конверт даёт явное поле версии протокола.
3. Меньше абстракций между кодом и проводом.

Цена: heartbeat, ack, дедупликацию и переподключение пишем сами.

## Конверт

Одинаковый в обе стороны:

```json
{
  "v": 1,
  "id": "c-7f3a",
  "type": "PLAY_CARD",
  "tableId": "uuid",
  "seq": 42,
  "ts": 1730000000000,
  "payload": { }
}
```

| Поле | Смысл |
|---|---|
| `v` | Версия протокола. Несовпадение → `ERROR: PROTOCOL_VERSION_UNSUPPORTED` |
| `id` | Уникальный id сообщения. У команд — для идемпотентности и ack |
| `type` | Тип команды или события |
| `tableId` | Всегда присутствует — по нему маршрутизация к столу (и в будущем к инстансу) |
| `seq` | Только у событий: **сквозной номер по матчу**, не по раздаче |
| `payload` | Данные |

## Команды (client → server)

Намерения. Никогда не результаты.

| Тип | Payload | Смысл |
|---|---|---|
| `TABLE_JOIN` | `{}` | Сесть за стол |
| `TABLE_LEAVE` | `{}` | Встать из-за стола |
| `TABLE_READY` | `{ready}` | Готовность к старту матча |
| **`PLAY_CARD`** | `{cardCode, targetCardCode?}` | ⭐ Универсальное «положить карту на стол» |
| `PASS` | `{}` | «Больше не подкидываю» — передаёт право второму соседу |
| `TAKE` | `{}` | Взять карты со стола |
| `TRANSFER` | `{cardCode}` | Перевести атаку на следующего |
| `PLAY_JOKER` | `{jokerIndex, ...}` | 🟨 Payload зависит от правил джокеров (OQ-2) |
| `RESYNC` | `{lastSeq}` | Догнать состояние после разрыва |
| `PING` | `{}` | Heartbeat |

Зарезервировано: `NAVES_*` — под механику навесов (OQ-3).

### `PLAY_CARD` — одна команда, два смысла ⭐

Смысл зависит от роли отправителя, и сервер определяет её сам:

| Роль отправителя | `targetCardCode` | Что произойдёт |
|---|---|---|
| Атакующий / подкидывающий | отсутствует | Атака или подкид |
| Защищающийся | **обязателен** | Отбить именно эту атакующую карту |

Защищающийся обязан указывать цель. Это не UI-удобство: при нескольких атакующих картах на
столе иначе невозможно однозначно зафиксировать, что чем отбито. `PLAY_CARD` от
защищающегося без `targetCardCode` → `ERROR: TARGET_REQUIRED`.

### `PASS` — явная фиксация отказа ⭐

Раунд не завершается «сам по себе». Обладатель права подкидывать обязан спасовать —
это и передаёт право второму соседу (следующему по часовой за защищающимся). Спасовавший
в этом раунде больше подкидывать не может.

## События (server → client)

| Тип | Payload | Кому |
|---|---|---|
| `STATE_SYNC` | Полная **персональная** проекция состояния | Одному игроку |
| `PLAYER_JOINED` / `PLAYER_LEFT` | `{userId, seatNo, displayName}` | Всем |
| `PLAYER_READY` | `{userId, ready}` | Всем |
| `MATCH_STARTED` | `{matchId, scoreLimit, seats[]}` | Всем |
| `DEAL_STARTED` | `{dealNo, trumpSuit, deckSize}` | Всем |
| `CARDS_DEALT` | Свои карты; у остальных — только количество | Персонально |
| `TURN_CHANGED` | `{attackerSeat, defenderSeat, canAttackSeat, deadlineTs}` | Всем |
| `CARD_PLAYED` | `{seatNo, cardCode, slot, kind: ATTACK\|DEFEND\|TRANSFER}` | Всем |
| `PLAYER_PASSED` | `{seatNo, nextAttackerSeat}` | Всем |
| `ATTEMPT_REJECTED` | `{seatNo}` — 🟨 **только факт, без карты** | Всем |
| `TRICK_RESOLVED` | `{outcome: BEATEN\|TAKEN, nextAttackerSeat}` | Всем |
| `CARDS_DRAWN` | `{drawn: [{seatNo, count}], deckLeft}` + свои карты | Персонально |
| `PLAYER_OUT` | `{seatNo, place}` | Всем |
| `CARD_HUNG` | 🟨 `{fromSeat, toSeat, cardCode}` — навесили карту в слот игрока | Всем |
| `SCORE_CHANGED` | `{scores: [{seatNo, delta, total}], reason}` | Всем |
| `DEAL_FINISHED` | `{dealNo, loserSeat, results[], scores[]}` | Всем |
| `MATCH_PAUSED` | `{reason, waitingForSeat, resumeDeadlineTs}` | Всем |
| `MATCH_RESUMED` | `{}` | Всем |
| `MATCH_ABORTED` | `{reason}` | Всем |
| `MATCH_OVER` | `{loserSeat, lossType, places[], scores[], ratingChanges[]}` | Всем |
| `ACK` | `{commandId, accepted}` | Отправителю |
| `ERROR` | `{code, message, commandId?}` | Отправителю |
| `PONG` | `{}` | Отправителю |

### `ATTEMPT_REJECTED` — попытка неверного хода 🟨

Необязательная социальная фишка (флаг `showRejectedAttempts`, реализуется последней).
Когда защищающийся положил карту, которая не бьёт указанную цель:

- ход отклоняется, состояние не меняется;
- фронт **отправителя** откатывает действие сразу, не дожидаясь сервера — для отзывчивости;
- остальные получают `ATTEMPT_REJECTED {seatNo}` и рисуют мелькнувшую **рубашку**.

Payload содержит только номер места. Какая именно карта — не передаётся никому: иначе это
утечка скрытой информации. Сервер валидирует ход в любом случае — откат на фронте это
только скорость реакции, не источник истины (ADR-003).

## Персональная проекция `STATE_SYNC` ⭐

```json
{
  "matchId": "uuid",
  "seq": 42,
  "matchStatus": "IN_PROGRESS",
  "scoreLimit": 100,
  "dealNo": 3,
  "phase": "DEFEND",
  "trumpSuit": "H",
  "deckLeft": 12,
  "myHand": ["A-spades", "7-hearts"],
  "mySeat": 2,
  "players": [
    {"seatNo": 0, "userId": "...", "displayName": "...", "cardsCount": 6,
     "hung": ["6-clubs"], "score": 40, "online": true, "passed": true},
    {"seatNo": 1, "userId": "...", "displayName": "...", "cardsCount": 4,
     "hung": ["Joker-1", "K-hearts"], "score": 25, "online": true, "passed": false}
  ],
  "table": [
    {"attack": "10-diamonds", "defend": null}
  ],
  "attackerSeat": 1,
  "defenderSeat": 2,
  "canAttackSeat": 1,
  "turnDeadlineTs": 1730000030000,
  "availableActions": [
    {"type": "PLAY_CARD", "cardCode": "7-hearts", "targetCardCode": "10-diamonds"},
    {"type": "TAKE"}
  ]
}
```

Четыре принципиальных момента:

0. ⭐ **`hung` — слот навесов, и он открытый.** Карты, навешенные на игрока, видны всем
   (🟨 требует подтверждения, OQ-14) — в отличие от руки. Это единственные чужие карты,
   которые вообще попадают в проекцию, и попадают они туда легально: без них игроки не могут
   оценивать положение, а джокер в чужом слоте — важнейшая информация за столом.
1. **Чужой руки в этом объекте нет физически.** Только `cardsCount`. Не «есть, но скрыты» —
   их нет в сериализованном виде вообще.
2. **`availableActions` приходит от сервера.** Фронт подсвечивает возможные ходы, не зная
   правил. Когда добавятся навесы, фронт не переучивается — просто получит новые типы
   действий в списке.
3. **Счёт матча в состоянии есть всегда** (`score` у каждого игрока, `scoreLimit`) — игрок
   должен видеть, насколько он близок к проигрышу, в любой момент.

`canAttackSeat` — у кого сейчас право подкидывать. Отдельно от `attackerSeat`, потому что
после паса право уходит второму соседу, а начавшим раунд остаётся прежний игрок.

## Пауза при отключении ⭐

```
клиент перестал отвечать
  → MATCH_PAUSED {reason: PLAYER_DISCONNECTED, waitingForSeat: 3, resumeDeadlineTs}
  → у всех останавливается таймер хода, показывается «Игрок 3 не может подключиться»
  → игрок вернулся  → MATCH_RESUMED, таймер хода продолжается С ОСТАТКА
  → не вернулся за disconnectGraceSeconds (60 с)
        → MATCH_ABORTED {reason: "Игрок 3 покинул игру"}
```

Таймер хода именно **приостанавливается**, а не тикает дальше: иначе за время разрыва у
игрока сгорит ход, и он вернётся уже наказанным за проблемы со связью.

## Переподключение и ресинк

```
разрыв → backoff (1s, 2s, 4s, 8s, макс 30s, с джиттером)
   → новый ws-ticket по REST
   → connect → TABLE_JOIN
   → RESYNC {lastSeq: 42}
       ├─ дыра небольшая → сервер досылает события 43..N
       └─ дыра большая / снапшот новее → полный STATE_SYNC
```

`seq` сквозной по матчу — клиент отслеживает один счётчик за всё время за столом, и переход
между раздачами не требует особой обработки при ресинке.

Клиент обязан:
- отслеживать `seq` и запрашивать `RESYNC` при обнаружении дыры;
- не применять события с `seq <= lastAppliedSeq` (защита от дублей);
- переотправлять неподтверждённые команды с тем же `id` — сервер дедуплицирует по `id`.

## Heartbeat

- Клиент шлёт `PING` каждые 20 сек, ждёт `PONG`.
- Нет `PONG` дважды подряд → соединение мертво, реконнект.
- Сервер, не получая активности, переводит матч в `PAUSED` и запускает
  `disconnectGraceSeconds`.

Нужно именно прикладное ping/pong: TCP-таймауты измеряются минутами, а у нас ход длится
30 секунд.

## Версионирование протокола

- `v` в конверте. Ломающее изменение → `v+1`.
- Сервер какое-то время поддерживает обе версии; клиент со старой `v` получает `ERROR`
  с `code = PROTOCOL_VERSION_UNSUPPORTED`.
- Новое **необязательное** поле или новый тип события версию не ломают — клиент обязан
  игнорировать неизвестные типы событий, а не падать.

## Лимиты и защита

- Rate limit на команды: не больше N в секунду с соединения.
- Максимальный размер сообщения ограничен.
- Любая команда проверяется на: мою ли очередь, за этим ли я столом, легален ли ход.
  Нелегальная команда → `ERROR`, состояние не меняется, соединение не рвётся.
